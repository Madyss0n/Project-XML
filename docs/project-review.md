# Анализ проекта и текущий этап

## Исходное состояние

Небольшой Python-проект с разделением ответственности: validator отвечает за XML/XSD,
repository преобразует XML в Book и сохраняет записи, models/db описывают SQLAlchemy и SQLite.
Это подходящая основа для курсовой: ядро валидации можно вызывать из разных интерфейсов.

Исходная схема описывала только плоскую книгу (name, author, publishDate).
Файлы test_validator.py и test_full.py — ручные сценарии с XML внутри Python,
а не автоматические тесты: некоторые ошибочные результаты только печатались.
Интерфейса выбора файла, редактирования и повторной проверки не было.
Диагностика XSD возвращалась в сыром виде, без рекомендаций.
README содержал имена файлов, не совпадавшие с реальными, и устаревший путь логов.

## Реализованные изменения

1. Независимый от интерфейса валидатор поддерживает выбор встроенной XSD или передачу пути.
2. Сохранён исходный вызов validate_xml(data) для книг и список строк .errors.
3. Добавлена структурированная диагностика и русские подсказки, основанные на типичных ошибках lxml.
4. Добавлена схема людей: базовый тип, наследование, вложенные контакты,
   ограничения email и курса, уникальность id.
5. Добавлен Tkinter-интерфейс: системный диалог выбора XML, редактор, ошибки,
   переход к строке, повторная проверка, сохранение копии и перечитывание файла.
6. Добавлены самостоятельные XML-файлы и автотесты, включая цикл исправления в интерфейсе.
7. Парсер не раскрывает внешние сущности, а документы с DOCTYPE отклоняются.

Tkinter выбран для текущего локального сценария и запуска из PyCharm без веб-сервера.
Ядро можно использовать позже в FastAPI без зависимости от Tkinter.
Текущая реализация синхронная: большие XML могут временно задерживать окно;
потоковая обработка и ограничения размера относятся к следующему этапу.

## Следующие шаги по исходному ТЗ

- Успешно проверенные книги и люди сохраняются одной транзакцией в validation_acces.
  Повторные проверки сохраняются как отдельные группы истории.
- Добавить простую кнопку GUI для просмотра документов и строк validation_acces.
- Добавить FastAPI, если итоговое ТЗ требует именно веб-сервис.
- Отдельно ввести бизнес-проверки (возраст, даты в будущем и допустимость связей).
- Уточнить политику дат книг: XSD xs:date допускает timezone, текущий repository использует
  strptime('%Y-%m-%d'), поэтому не все допустимые XSD-даты книг импортируются в БД.
- Путь SQLite закреплён за каталогом проекта; таблица validation_errors хранит диагностику XML.
- Привести логирование к одному месту: app/logger.py пишет в log/app_log, а .gitignore исключает logs/;
  файл log/app_log уже отслеживается Git и был изменён до начала текущей работы.

Данные books.db и существующая модель Book не мигрировались. Проверка сохранения книг
в автотестах выполняется на отдельной SQLite в памяти.
