# XML-валидатор с SQLite и логгером

Учебное приложение на Flask: загрузить XML в браузере, проверить по XSD, увидеть
ошибки и сохранить результат в SQLite. Веб-интерфейс использует существующий
валидатор из `app/validator.py`, без отдельного frontend-проекта и JavaScript.

## Запуск

В PyCharm выберите `.venv/Scripts/python.exe`, установите зависимости и запустите
`main.py`. Из терминала в корне проекта:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe main.py
```

Откройте в браузере **http://127.0.0.1:5000/**. Пока работает сайт, оставляйте процесс
Python запущенным. Для остановки нажмите Stop в PyCharm или Ctrl+C в терминале.
Сервер доступен только на текущем компьютере, отладчик выключен.

Выберите схему `people` или `books`, загрузите XML из `examples/` и нажмите
«Проверить XML». При успехе появится таблица извлечённых полей; при ошибке - строка,
XPath и подсказка. Загруженный XML остаётся в поле редактирования под результатом.
Исправьте текст прямо в браузере и нажмите «Проверить» под полем. Повторно выбирать
файл не нужно; текущий текст и выбранная схема сохраняются после проверки.
Можно менять схему в форме редактора. Исходный файл на компьютере не перезаписывается.
Текст редактора и объявление кодировки XML приводятся к UTF-8.
Размер запроса ограничен 2 МБ; загрузка читается в памяти, копия XML в проекте не создаётся.

Прямые зависимости: `lxml` и `Flask`. Jinja2 и остальные зависимости Flask
устанавливаются автоматически. SQLite и логирование входят в Python.
Прежнее окно Tkinter можно отдельно запустить через `python -m app.gui`;
для него нужен установленный Tcl/Tk.

## Как работает

1. `GET /` вызывает функцию `validate()` в `web.py` и показывает форму из HTML-шаблона.
2. Загрузка отправляет `POST /` с `action=upload`: Flask читает файл из `request.files`.
   Редактор отправляет `action=edit`: текущий текст берётся из `request.form['xml_text']`.
   В обоих случаях схема берётся из `request.form['schema']`.
3. `validate_xml()` строит дерево через `etree.fromstring()` и проверяет его через `etree.XMLSchema`.
4. При успехе поля книги или человека записываются в `validation_acces`.
5. При ошибке диагностика записывается в `validation_errors` и лог.
6. Jinja2 подставляет результат в HTML и возвращает страницу браузеру.

Веб-страница показывает результат последней отправленной проверки. При нажатии
«Проверить» выполняется обычный POST и обновляется вся страница, JavaScript не нужен.
История из БД относится к следующим шагам. Для таблицы результатов
используется та же функция `parse_records()`, что и при записи в SQLite.

DOCTYPE не поддерживается, внешние сущности не раскрываются.
Строки одного документа записываются одной транзакцией: либо все, либо ни одной.
Если SQLite недоступна, приложение отдельно сообщает о сбое записи.

Схема People содержит абстрактный `PersonType`: fullName, birthDate, contacts,
обязательный уникальный id. `StudentType` наследует его и добавляет university и
course (1-6). `EmployeeType` добавляет organization и position. В contacts допускаются
1-3 email и необязательный phone. Конкретный тип задаётся через `xsi:type`.

## База данных

`books.db` всегда находится в корне проекта, независимо от папки запуска.
Таблицы и индексы описаны обычным SQL в `app/database.py`. Создаются при первой
записи и проверяются один раз за запуск. Существующие записи БД сохраняются.

| Таблица | Содержание |
| --- | --- |
| `validation_acces` | Поля корректных книг, студентов и сотрудников |
| `validation_errors` | Ошибки XML и подсказки |
| `books` | Старые записи книг, если остались от прежней версии; новый код таблицу не использует |

Общие поля истории: `id`, `validation_id`, `occurred_at` (UTC), `source_name`,
`schema_path`. `validation_id` группирует строки одной попытки. Каждая отправка формы
добавляет новую попытку. Обновление страницы с повторной отправкой POST тоже добавит
записи; простой GET главной страницы ничего не записывает. Между таблицами нет внешних ключей.

В `validation_acces` дополнительно хранятся:

- `record_type`: book, student или employee;
- книга: `name`, `author`, `publish_date`;
- человек: `person_id`, `full_name`, `birth_date`, `email1`, `email2`, `email3`, `phone`;
- студент: `university`, `course`;
- сотрудник: `organization`, `position`.

Одна книга или человек - одна строка. Неиспользуемые поля имеют значение NULL.
Даты хранятся как XML-текст. Исходный XML целиком не сохраняется.
В `validation_errors` дополнительно хранятся `category`, `line`, `column`,
`xpath`, `message`, `suggestion`. Значение 0 означает неизвестную позицию.

Для просмотра в DBeaver создайте подключение SQLite, укажите файл `books.db`,
откройте Tables → таблица → Data. Структура доступна на вкладке Diagram / ER Diagram.

```sql
SELECT * FROM validation_acces ORDER BY id DESC;
SELECT * FROM validation_errors ORDER BY id DESC;
SELECT name, sql FROM sqlite_master WHERE type = 'table';
```

## Логирование

`log/app_log` содержит время, уровень, имя модуля и сообщение. Записи также
выводятся в консоль: INFO для успеха, WARNING для ошибок XML, ERROR со стеком для
технических сбоев. Время в логе локальное, в SQLite - UTC.

## Вызов из Python

```python
from app.validator import validate_file, SCHEMAS, XMLValidationError, ValidationStorageError

try:
    root = validate_file('examples/people_valid.xml', SCHEMAS['people'])
    print('Сохранено записей:', len(root))
except XMLValidationError as error:
    print(*error.errors, sep='\n')
except ValidationStorageError as error:
    print(error)
```

`validate_xml(data, schema_path, source_name='document.xml')` проверяет байты.
Без схемы используется `books.xsd`. Ошибка чтения файла возвращается как OSError,
загрузки XSD - RuntimeError. Веб-страница различает ошибки XML и технические сбои:
422 - XML не прошёл проверку, 400 - неверно заполнена форма, 413 - превышен размер,
503 - XML корректен, но данные не записаны в БД, 500 - сбой выполнения проверки.
