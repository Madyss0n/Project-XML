# Курсовая: валидация XML по XSD

Проект проверяет XML-документы, показывает ошибки и помогает исправить их.
Есть оконное приложение на Tkinter и отдельная цепочка импорта книг в SQLite.

## Запуск в PyCharm

1. Откройте проект и выберите интерпретатор `.venv\Scripts\python.exe`.
2. Запустите `main.py` через Run. Откроется окно валидатора.
3. Выберите схему `people` или `books` и нажмите «Открыть XML…».
4. Выберите файл из `examples/`. Проверка выполнится сразу после открытия.
5. Нажмите на ошибку: ниже появится подсказка и XPath, в редакторе подсветится строка.
6. Исправьте текст и нажмите F5 («Проверить»). Проверяется текущий текст редактора.
7. Нажмите «Сохранить как…», чтобы записать исправленный документ в UTF-8.

Если исправляете XML в PyCharm, нажмите «Перечитать файл» в приложении.
Перед закрытием или заменой несохранённого текста приложение спрашивает подтверждение.
Оригинальный файл не изменяется до сохранения. Диалог сохранения подтверждает перезапись.
После изменения текста или схемы старый результат проверки сбрасывается.

Из терминала в корне проекта:

```powershell
.venv/Scripts/python.exe main.py
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

В новом окружении: `python -m pip install -r requirements.txt`.
Tkinter входит в обычную установку Python для Windows; при установке Python должен быть включён Tcl/Tk.
Тесты интерфейса требуют графической сессии. Только ядро: `python -m unittest discover -s tests -p test_validation.py -v`.

## Что есть в проекте

| Файл | Назначение |
| --- | --- |
| `main.py` | Точка входа для PyCharm |
| `app/gui.py` | Выбор файла, XML-редактор, ошибки, подсказки, повторная проверка |
| `app/validator.py` | Парсинг XML, XSD-валидация, структурированные ошибки |
| `app/schemas/people.xsd` | Учебная схема с общим типом человека и наследованием типов |
| `app/schemas/books.xsd` | Исходная схема книг |
| `examples/` | 8 XML: 2 корректных и 6 некорректных для двух схем |
| `tests/` | Автотесты валидатора, интерфейса и совместимости импорта книг |
| `app/models.py`, `app/db.py`, `app/repository.py` | Модель Book и сохранение книг в SQLite |
| `docs/people-schema.md` | Описание структуры, типов, ограничений и сценариев демонстрации |
| `docs/project-review.md` | Анализ исходного состояния и дальнейшие задачи |

## Программный интерфейс

```python
from app.validator import validate_file, validate_xml, XMLValidationError, SCHEMAS

try:
    root = validate_file('examples/people_valid.xml', SCHEMAS['people'])
    print('Записей:', len(root))
except XMLValidationError as exc:
    for issue in exc.issues:
        print(issue.line, issue.path, issue.message, issue.suggestion)
```

`validate_xml(data)` по умолчанию использует `books.xsd`: старый код импорта книг совместим.
`XMLValidationError.errors` остаётся списком строк; `.issues` содержит категорию, строку,
столбец, XPath, исходное сообщение lxml и подсказку на русском. У XSD-ошибок столбец
часто равен 0: библиотека не сообщает точный столбец.
Ошибка чтения файла — `OSError`; ошибка загрузки/компиляции схемы — `RuntimeError`.
Схема компилируется при каждой проверке, поэтому изменения XSD видны без перезапуска.

Сначала проверяется синтаксис, затем соответствие XSD. При сломанном синтаксисе
проверка XSD невозможна. После исправления могут появиться новые ошибки, ранее
скрытые нарушением структуры. Подсказки основаны на диагностике валидатора;
они не заменяют XSD и не исправляют документ автоматически.
DOCTYPE и пользовательские сущности не поддерживаются; внешние сущности не раскрываются.

## Границы текущего этапа

Оконное приложение валидирует документы и сохраняет XML. Оно не импортирует людей в БД.
В БД реализована только модель Book. Для людей следующим этапом нужны отдельные
ORM-модели, таблицы контактов/адресов, транзакционный импорт и тесты связей.
FastAPI и Docker пока не реализованы.

Исходные ручные сценарии остались: `test_validator.py`, `test_db_manual.py`, `test_full.py`.
Последние два работают с файловой БД; `test_full.py` при каждом запуске добавляет книги.
Новые автотесты используют БД в памяти и не меняют `books.db`.
